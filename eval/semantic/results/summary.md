## Interpretation
- All arm-level CIs overlap (A null [4.3, 21.4] vs C [2.1, 16.2]; A usable@3 [67, 88.8] vs C [76.2, 94.4]). The gains are **directional, not significant at this sample size** (n=50 per arm).
- C lowers null rate 10%->6% and success@3 56%->58%, and cuts questions/journey 0.46->0.34; usable@3 is flat at 88%. No kind regressed on null rate; real_suggest usable@3 dipped 90%->85% (n=20) — see the degraded queries above.
- The fallback does exactly what it is designed to do: it is byte-identical for the 36/50 queries lexical already resolves (no-op guarantee: 293/293 resolved queries identical across all 358 canary + study + eval-v2 panel queries) and only touches the 36 lexical nulls.

## Limitations (do not omit)
- Relevance is judged by a single Qwen model (temp 0, thinking off) plus no multi-annotator ground truth; 40-result hand labelling was skipped per the agreed cut line (n=50 panel) — agreement with the judge is therefore unmeasured.
- `real_suggest` queries are real-query-shaped Google Suggest autocompletes, not logged shopper queries; there are no real users.
- The catalogue is a demo catalogue (US-converted + synthetic India layer), so absolute relevance numbers are indicative.
- Semantic matching can return plausible-but-wrong neighbours for out-of-catalogue products; tau/margin trade recall against this and were tuned on the dev split only.
- English/Hinglish coverage depends on the embedding model; romanised Hinglish is only partially handled (see hinglish kind row).
- Dead-end false-resolve is measured at n=4; the 100% rate reflects the baseline rescue path, not the semantic layer (see notes).

## Presentation line (filled from artifacts)
> A semantic fallback (multilingual e5-small embeddings, int8 index, brute-force search) invoked only when lexical search returned <2 on-intent results reduced the null rate on a frozen held-out panel (n=50) from 10% [4.3-21.4] to 6% [2.1-16.2] (directional; CIs overlap), raised Qwen-judged success@3 from 56% to 58% (usable@3 flat at 88%), and cut questions per journey from 0.46 to 0.34, with semantic latency p95 32 ms. Out-of-catalogue queries: the semantic layer itself rejected all 4 (below threshold); the 100% (4/4) app-level 'false-resolve' is inherited from the baseline category-rescue path (identical in the lexical-only arm).
